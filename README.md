## 🌐 Overview

Public development projects require effective monitoring of fund allocation, expenditure, implementation progress, and administrative accountability.

NIDHINETRA is designed to provide a unified monitoring experience that helps stakeholders access relevant information, identify unusual patterns, and prioritize projects requiring attention.

### 🎯 Core Objectives

* **Visibility:** Bring fund and project information into a unified monitoring experience.
* **Risk Identification:** Surface unusual expenditure patterns, delays, and data inconsistencies.
* **Accountability:** Organize access according to administrative responsibilities.
* **Decision Support:** Present relevant information through role-specific dashboards.

## 🏛️ Four-Level Monitoring Architecture

NIDHINETRA is designed around four stakeholder roles, supporting monitoring at different administrative levels.

| Stakeholder                      | Primary Responsibility                                         |
| -------------------------------- | -------------------------------------------------------------- |
| 🏛️ **Ministry Admin**           | National-level monitoring and oversight.                       |
| 🗺️ **State Nodal Authority**    | State-level fund and project monitoring.                       |
| 📍 **District Authority**        | District-level implementation monitoring and project review.   |
| 👤 **Member of Parliament (MP)** | Constituency-level development monitoring and progress review. |

Each role is intended to access relevant information and perform permitted actions according to its administrative responsibilities.

## 🧠 AI-Powered Risk Intelligence

NIDHINETRA aims to help stakeholders identify patterns that may require closer examination:

* Unusual project expenditure patterns.
* Potential duplicate project records.
* Unexpected project implementation delays.
* Inconsistencies in financial and project records.
* Potential inefficiencies in fund utilization.

**Responsible AI:** An anomaly is a signal for investigation, not proof of fraud. Analytical findings require validation and human review before decisions are made.

## 🔒 Security and Accountability

* **Role-based authorization:** Control access to protected operations.
* **Account approval:** Support administrator-managed account activation.
* **Credential protection:** Keep secrets and sensitive configuration out of source control.
* **Data integrity:** Validate inputs and maintain consistent records.
* **Human oversight:** Verify analytical findings before consequential decisions.

Security must be enforced by the backend, not just by hiding frontend features.
