## 🌐 Overview

Public development projects require effective monitoring of fund allocation, expenditure, implementation progress, and administrative accountability.

NIDHINETRA is designed to support this process through a unified monitoring platform that helps stakeholders access relevant information, identify unusual patterns, and prioritize projects that may require attention.

### 🎯 Core Objectives

* **Improve Visibility:** Bring fund and project information into a unified monitoring experience.
* **Identify Potential Risks:** Surface unusual expenditure patterns, delays, and data inconsistencies.
* **Strengthen Accountability:** Organize access according to administrative responsibilities.
* **Support Better Decisions:** Present relevant information through role-specific dashboards.

## 🏛️ Four-Level Monitoring Architecture

NIDHINETRA is designed around four stakeholder roles, supporting monitoring at different administrative levels.

| Stakeholder                      | Primary Responsibility                                         |
| -------------------------------- | -------------------------------------------------------------- |
| 🏛️ **Ministry Admin**           | National-level monitoring, oversight, and administration.      |
| 🗺️ **State Nodal Authority**    | State-level fund and project monitoring.                       |
| 📍 **District Authority**        | District-level implementation monitoring and project review.   |
| 👤 **Member of Parliament (MP)** | Constituency-level development monitoring and progress review. |

The architecture aims to ensure that each stakeholder receives relevant information and can perform permitted actions within their assigned responsibilities.

## 🧠 AI-Powered Risk Intelligence

NIDHINETRA aims to help stakeholders identify patterns that may require closer examination, including:

* Unusual project expenditure patterns.
* Potential duplicate project records.
* Unexpected project implementation delays.
* Inconsistencies between financial and project records.
* Potential inefficiencies in fund utilization.

**Responsible AI principle:** An anomaly is a signal for investigation, not proof of fraud. Risk indicators should be explainable, validated against reliable data, and reviewed by authorized personnel before decisions are made.

## 🔒 Security and Accountability

NIDHINETRA's security approach focuses on:

* **Role-based authorization:** Enforce permissions on protected operations.
* **Controlled account approval:** Support administrator-managed account activation.
* **Credential protection:** Keep secrets and sensitive configuration out of source control.
* **Data integrity:** Validate inputs and maintain consistent records.
* **Human oversight:** Require verification of analytical findings before consequential decisions.

Security controls should be enforced by the backend, not solely by frontend visibility or routing.
